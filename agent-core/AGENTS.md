# agent-core: guide for coding agents

Rice Agent is an [eve](https://github.com/vercel/eve) agent (eve `1.0.0-rc.3`) running Grok through `@ai-sdk/xai`, with a Next.js 16 web UI generated by `eve add channel/web`. It runs locally: no Vercel account, no Docker, no database server.

## Before you write code

- **eve:** read the bundled docs in `node_modules/eve/docs/` (start at `README.md`). They match the installed version. Don't rely on memory: eve is new and its APIs changed between versions. The project skill `.claude/skills/eve` points to the same place.
- **Next.js 16:** read `node_modules/next/dist/docs/` before touching `apps/web/`. It has breaking changes, as `apps/web/AGENTS.md` warns.

## Environment

- Node 24 is required (`nvm use` reads `.nvmrc`); the shell default may be older. Use pnpm, never npm or yarn.
- `.env.local` holds `XAI_API_KEY` (and optionally `GROK_MODEL`, `GROK_SEARCH_MODEL`). eve loads it automatically. Never print or commit it.
- **Keep `.npmrc` (`ignore-workspace-root-check=true`).** `eve add ...` installs with a plain `pnpm add`. This folder is a pnpm workspace root, so without it pnpm fails with `ERR_PNPM_ADDING_TO_ROOT`, and eve only says "Dependency installation failed".
- The Python side needs `uv`: run `pnpm setup:py` once.

## Layout

```
agent/
  agent.ts            model: xai.responses(GROK_MODEL ?? "grok-4.7"), reasoning "low"
  instructions.md     system prompt: forecaster only. Don't claim features that aren't built
  sandbox.ts          JustBashSandbox (pure JS shell, no Docker). Keep it
  channels/eve.ts     auth: localDev() only
  lib/rice.ts         THE data layer: types + functions used by tools AND the web API
  tools/rice_*.ts     forecast, market snapshot, news search, data refresh
  tools/web_search.ts disables eve's built-in web_search (no support for direct xAI)
  skills/price-outlook/SKILL.md   the outlook procedure (loaded on demand)
apps/web/
  app/_components/agent-chat.tsx  generated chat, extended with an `intro` (first thread message)
  app/_components/agent-message.tsx  renders chat cards for card tools
  app/api/rice/*/route.ts         GET routes calling agent/lib/rice.ts
  components/rice/                intro, forecast chart/card, market card, news card, tool-card map
```

`apps/web` imports agent code through the `@agent/*` path alias (`apps/web/tsconfig.json`).

## Principles of this design

1. **One data layer.** The UI and Grok must see the same numbers. Put new data functions in `agent/lib/rice.ts` (or a sibling module in `agent/lib/`). Call them from a tool *and* from an `/api/rice/*` route; never fetch data a second way in the UI.
2. **One thread.** No sidebars or separate dashboards. The intro is the first message of the thread, tool results render as cards inside it, and the conversation continues below.
3. **Simple story.** The first screen is a few sentences and one chart. Put method details behind a collapsed "How this is made". Don't add buttons or stat tiles without a reason.
4. **Fast turns.** A turn should finish in about a minute. Main reasoning is `"low"`. The news search (`rice_market_news`) costs 30–90 s per call, so the skill allows one news call per answer. Keep skills short, with few tool calls. Before raising effort or adding calls, measure (see Testing).

## Recipes

**Add a tool with a chat card**

1. Write the function and its output type in `agent/lib/rice.ts`.
2. Add `agent/tools/<name>.ts` with `defineTool` (Zod `inputSchema`, a `label`, and a `description` written for the model, naming its sources). If the output is large, use `toModelOutput` to give the model only the gist; the UI still gets the full output.
3. If the UI needs it on load, add `apps/web/app/api/rice/<name>/route.ts` calling the same function.
4. For a card, write a component in `apps/web/components/rice/` and register it in `tool-card.tsx` (`CARD_TOOLS` and the `switch`). Other tools appear as trace lines.
5. Mention the tool in `agent/instructions.md` and, if part of a procedure, in the skill.

**Add or change a skill:** `agent/skills/<name>/SKILL.md`, with a `description` in the frontmatter that says when to load it. Say how many tool calls to make and how long the answer should be.

**Add an eve integration:** `pnpm exec eve add <item>` (search with `eve registry search`). For the web channel, the non-interactive answers are in `README.md`.

**UI styling:** use the theme tokens in `apps/web/app/globals.css` (`--rice-*` for charts, shadcn tokens otherwise); they cover light and dark. Charts use recharts. Check the layout at phone width.

## Testing

```bash
pnpm typecheck                                    # agent code
pnpm exec tsc --noEmit -p apps/web/tsconfig.json  # web app
pnpm dev:web                                      # http://localhost:3000, agent included
```

Exercise a real turn over HTTP while `dev:web` runs. Read the stream to see each tool call and its timing:

```bash
curl -s -X POST localhost:3000/eve/v1/session -H 'Content-Type: application/json' \
  -d '{"message":"Should we buy Carnaroli now or wait?"}'          # -> sessionId
curl -sN localhost:3000/eve/v1/session/<sessionId>/stream          # NDJSON; facts[].type
```

Look for `call.requested` / `call.settled` per tool and `turn.settled` at the end. `GET /eve/v1/info` lists the loaded tools and skills. Stop any dev server you start.

## Don't

- Don't swap the model to an AI Gateway string (`"xai/..."`): that needs a Vercel account. Keep `xai.responses(...)`.
- Don't add Docker or a database. eve's local world stores sessions in `.eve/`.
- Don't edit `node_modules`. If eve misbehaves, read its docs or `CHANGELOG.md`.
